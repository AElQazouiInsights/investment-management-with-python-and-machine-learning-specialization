# Teaching standard for all chapters

Apply this standard when writing new chapters and reviewing existing ones across all four courses. Students should be able to follow the reasoning before running the code. When an explanation is difficult to follow, improve its example, definitions, or pacing rather than assume the student should already understand it.

## Teach one idea at a time

1. **Ask a concrete financial question.** Explain the decision, the quantities involved, and why the question matters.
2. **Show a small numerical example.** Use a short table or a few observations. Define each new term, symbol, unit, and date convention when it first appears.
3. **Work through the calculation.** Substitute the numbers into the formula and show the intermediate steps. Introduce a simple baseline before a more elaborate method.
4. **Make the result visible.** Use ECharts where a graph helps explain the relationship. Describe the axes, units, observations, and what students should notice. Connect a plotted value to the worked calculation.
5. **Reproduce it in Python.** The first implementation should calculate the same numbers. Explain important operations and inputs before introducing a reusable helper or library abstraction.
6. **Change one assumption.** Ask students to predict what will happen, then calculate and explain the difference. Use ipywidgets when a control makes the relationship easier to explore.
7. **Check understanding.** Give a short exercise with a hint and a worked answer or explanation. Include interpretation, not only a numerical result.

Repeat this progression for new concepts within a chapter. Build toward a larger application after the small examples are understood. A chart generated by a Python cell can appear immediately after that cell; explain its purpose before the student runs it and interpret its output alongside it.

## Examples and evidence

- Every newly introduced formula needs a numerical illustration. Explain intermediate steps instead of jumping from notation to a library call.
- Every chart needs an interpretation: what changes, why it changes, and what the chart does not establish. Tables, charts, and code must agree on values, labels, dates, and units.
- Use clearly labeled synthetic data when a known relationship helps isolate a concept. State the construction and seed. Explain the additional uncertainty when moving to historical data.
- For prediction, show what information is available at the decision date. Introduce training, validation, and testing through an example before using the terminology without explanation.
- For portfolio decisions, state the objective, constraints, and timing. Separate model assumptions, historical observations, and realized investment outcomes.
- Exercises should have enough feedback for independent study. The capstone can combine previously explained methods and ask students to justify a choice; there need not be one preferred portfolio.

## Language and presentation

Use plain, precise language and short sections. Avoid promotional wording, unexplained jargon, and phrases such as “obviously” or “simply” that conceal a missing step. Keep explanations as short as understanding allows; do not shorten away the reasoning.

Preserve the existing website design, editable browser-run Python, ECharts, and selective ipywidgets. Link to a prerequisite when needed and briefly recall the part used in the current calculation.

## Review question

Can a student explain the question, reproduce the small calculation, read the graph, and predict the effect of one changed assumption? If not, identify the missing teaching step before adding more complexity.

This guide defines the review standard; it does not certify that every existing chapter has already been audited against it.
