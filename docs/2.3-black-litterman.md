# Black–Litterman: Reference Portfolios, Views, and Uncertainty

The [previous chapter](./2.2-covariance.md) improved the risk inputs used by portfolio optimization. Expected returns present another difficulty: small changes in estimated means can produce large changes in optimal allocations. **Black–Litterman** starts from a reference portfolio and combines its implied expected returns with explicit investor views and their uncertainty.

The model makes the assumptions behind a tilt visible. It does not make the reference portfolio correct, turn opinions into facts, or guarantee better performance. We will distinguish three separate decisions: constructing a prior, updating beliefs, and choosing an allocation under constraints.

The first examples use hypothetical **one-year** inputs. Returns and views are decimals, covariance is in squared return units, and expected returns are **excess of a common known cash return**. Run the examples in order; the interactive experiment also runs independently because its helper contains the stated two-asset inputs.

import json

## Start from an Allocation, Not a Sample Mean

Let $\mathbf w_0$ be reference risky-asset weights, $\Sigma$ their return covariance, and $\delta>0$ a risk-aversion coefficient. For expected excess returns $\boldsymbol\mu$, consider mean–variance utility:

$$U(\mathbf w)=\mathbf w^T\boldsymbol\mu-\frac{\delta}{2}\mathbf w^T\Sigma\mathbf w.$$

First allow unrestricted risky positions with cash financing the remaining budget. The first-order condition is:

$$\boldsymbol\mu-\delta\Sigma\mathbf w=\mathbf0.$$

Reverse the problem: which expected excess returns make the reference allocation optimal? The answer is:

$$\boxed{\boldsymbol\Pi=\delta\Sigma\mathbf w_0}.$$

These **implied returns** depend on covariance, risk aversion, and the reference weights. They are not historical average returns. A market-capitalization reference is motivated by an equilibrium interpretation; a policy benchmark instead produces a policy-implied prior. Calling an arbitrary selected portfolio “the market” does not establish equilibrium.

If optimization were restricted from the outset to fully invested risky portfolios, the first-order condition would also contain a budget multiplier: $\boldsymbol\mu=\delta\Sigma\mathbf w_0+\lambda\mathbf1$. Weights alone would not identify that common return level. The cash-financed formulation above motivates the conventional choice $\lambda=0$.

### A Two-Asset Hand Calculation

Use an Equity/Bonds reference with weights 60%/40%. Equity volatility is 20%, bond volatility 10%, and correlation 0.30, so covariance is $0.30(0.20)(0.10)=0.006$. With $\delta=2.5$:

$$
\Sigma=\begin{pmatrix}0.04&0.006\\0.006&0.01\end{pmatrix},\quad
\boldsymbol\Pi=2.5\begin{pmatrix}0.04(0.6)+0.006(0.4)\\0.006(0.6)+0.01(0.4)\end{pmatrix}
=\begin{pmatrix}0.066\\0.019\end{pmatrix}.
$$

The implied expected excess returns are **6.6% for Equity** and **1.9% for Bonds**. If the matching cash return were 2%, total expected returns would be 8.6% and 3.9%; do not add cash to the model's excess-return inputs themselves.

```python:line-numbers
assets = pd.Index(["Equity", "Bonds"])
sigma = pd.DataFrame([[0.04, 0.006], [0.006, 0.01]], index=assets, columns=assets)
reference_weights = pd.Series([0.60, 0.40], index=assets)
risk_aversion = 2.5
pi = pok.implied_returns(sigma, reference_weights, delta=risk_aversion)
print(pd.DataFrame({"Reference weight (%)": reference_weights * 100,
                    "Implied excess return (%)": pi * 100}).to_string(float_format=lambda x: f"{x:.3f}"))
```
<Editor id="bl-implied-returns" />

For an invertible $\Sigma$, substituting $\Pi$ back into $\mathbf w^*=\Sigma^{-1}\Pi/\delta$ recovers the reference. Use a linear solve rather than explicitly forming an inverse:

```python:line-numbers
recovered_reference = pd.Series(np.linalg.solve(sigma, pi) / risk_aversion, index=assets)
reference_excess_mean = reference_weights @ pi
reference_variance = reference_weights @ sigma @ reference_weights
print("Recovered risky weights (%):")
print((recovered_reference * 100).to_string(float_format=lambda x: f"{x:.3f}"))
print(f"Reference expected excess return: {reference_excess_mean:.3%}")
print(f"Reference variance: {reference_variance:.6f}")
print(f"Implied risk aversion: {reference_excess_mean / reference_variance:.3f}")
```
<Editor id="bl-reference-recovery" />

The reference's expected excess return is 4.72% and variance 0.01888, so their ratio is 2.5. This identity motivates estimating market risk aversion from an expected market premium divided by variance. A noisy historical average, especially a negative one, is not automatically a defensible positive risk-aversion estimate.

**Try it:** change `risk_aversion` to 5 and rerun both cells. Implied returns double, while reverse optimization with the same coefficient recovers the same weights. Risk aversion controls the mean–variance trade-off; it is not a view-confidence parameter.

## Encode Views and Their Uncertainty

Let $N$ be the number of assets and $K$ the number of views. The **pick matrix** $P$ has shape $K\times N$, and $Q$ is a $K$-element vector specifying views about expected excess returns:

$$Q=P\boldsymbol\mu+\boldsymbol\eta,\qquad \boldsymbol\eta\sim\mathcal N(\mathbf0,\Omega).$$

Rows of $P$ identify the exposures in each view. $Q$ contains the stated expected returns or return spreads. $\Omega$ is the covariance of **view errors about the means**, not the covariance of asset returns.

- **Absolute view:** Equity's expected excess return is 8%. Use $P=[1,0]$ and $Q=0.08$.
- **Relative view:** Equity's expected return exceeds Bonds' by 8 **percentage points**. Use $P=[1,-1]$ and $Q=0.08$.

The same number has different meanings in these two statements. A relative view is a difference of expected returns, not “Equity grows 8% faster” as a ratio of wealth levels.

For a view originally stated in total-return units, subtract the cash contribution:

$$Q_{\rm excess}=Q_{\rm total}-r_fP\mathbf1.$$

For a zero-net-exposure relative view, $P\mathbf1=0$, so cash cancels. For an absolute asset view, it does not.

```python:line-numbers
view_examples = pd.DataFrame([[1.0, 0.0], [1.0, -1.0]], columns=assets,
                             index=["Equity absolute", "Equity minus bonds"])
total_view_returns = pd.Series([0.08, 0.08], index=view_examples.index)
cash_assumption = 0.02
excess_view_returns = total_view_returns - cash_assumption * view_examples.sum(axis=1)
print(view_examples)
print("Views converted from total to excess units (%):")
print((excess_view_returns * 100).to_string())

# The main experiment uses the relative view only.
P = view_examples.loc[["Equity minus bonds"]]
Q = pd.Series([0.08], index=P.index)
tau = 0.05
C = tau * sigma
Omega = pok.omega_uncertain_prior(sigma, tau, P)
print("Default view-error covariance:")
print(Omega.to_string(float_format=lambda x: f"{x:.6f}"))
```
<Editor id="bl-view-construction" />

The converted absolute view is a 6% excess return; the relative view remains 8%. The named rows and columns are part of the calculation: assets, views, and covariance matrices must match by meaning, not merely by array position.

### Prior Uncertainty Versus View Uncertainty

The Bayesian formulation treats the unknown expected excess-return vector as:

$$\boldsymbol\mu\sim\mathcal N(\boldsymbol\Pi,C),\qquad C=\tau\Sigma,\quad\tau>0.$$

$\Sigma$ describes return variability conditional on the mean. $C$ describes uncertainty **about the mean**. The scalar $\tau$ specifies the prior uncertainty scale; it is not automatically $1/T$ unless a separate estimation argument justifies that choice.

Smaller entries in $\Omega$ indicate more precise views. Off-diagonal entries represent correlated view errors. A diagonal $\Omega$ assumes those errors are uncorrelated; it does not follow merely because the views have different names.

The toolkit's default is the common heuristic:

$$\Omega=\operatorname{diag}(PCP^T).$$

For our single relative view, $PCP^T=0.05(0.04+0.01-2\times0.006)=0.0019$. The default assigns the view error the same variance as the prior uncertainty in that expected spread. Its standard deviation is $\sqrt{0.0019}\approx4.359$ percentage points—not a claim that the view has a particular probability of being correct.

## Derive the Posterior Update

Assume view errors are independent of the prior mean uncertainty. When $C$ and $\Omega$ are positive definite, combining the Gaussian prior and likelihood is equivalent to minimizing:

$$
\frac12(\boldsymbol\mu-\Pi)^TC^{-1}(\boldsymbol\mu-\Pi)
+\frac12(Q-P\boldsymbol\mu)^T\Omega^{-1}(Q-P\boldsymbol\mu).
$$

The first term penalizes deviations from the prior; the second penalizes deviations from the views. More precise information receives more weight. Differentiating gives:

$$
(C^{-1}+P^T\Omega^{-1}P)\boldsymbol\mu
=C^{-1}\Pi+P^T\Omega^{-1}Q.
$$

An equivalent update, which avoids explicitly inverting $C$ or $\Omega$, is:

$$
\boxed{\boldsymbol\mu_{BL}=\Pi+CP^T(PCP^T+\Omega)^{-1}(Q-P\Pi)}.
$$

$Q-P\Pi$ is the **innovation**: the difference between the stated views and what the prior already implies. $CP^T$ propagates each view through the covariance structure, so an asset can move even when its coefficient in that view is zero.

The posterior covariance of the uncertain mean is:

$$\boxed{M=C-CP^T(PCP^T+\Omega)^{-1}PC}.$$

The implementation solves the conditioning system rather than forming its inverse. Independent exact views can also be handled through this update with $\Omega=0$, provided $PCP^T+\Omega$ is nonsingular. Redundant exact views require reformulation; silently adding numerical noise would change the model.

### Complete the Two-Asset Calculation

The prior relative mean is $P\Pi=0.066-0.019=0.047$. The stated view is 0.08, so the innovation is 0.033. Also:

$$
CP^T=\begin{pmatrix}0.0017\\-0.0002\end{pmatrix},\qquad
PCP^T+\Omega=0.0038.
$$

Thus the update adds approximately 1.4763 percentage points to Equity and subtracts 0.1737 percentage points from Bonds. The posterior means are **8.0763% and 1.7263%**, giving a spread of **6.35%**, halfway between the prior 4.7% spread and the 8% view.

```python:line-numbers
prior_spread = float((P @ pi).iloc[0])
innovation = Q - P @ pi
cross_covariance = C @ P.T
conditioning_variance = float((P @ C @ P.T + Omega).iloc[0, 0])
hand_mean = pi + cross_covariance.iloc[:, 0] * innovation.iloc[0] / conditioning_variance
posterior_mean, predictive_covariance = pok.black_litterman(
    reference_weights, sigma, P, Q, Omega=Omega, delta=risk_aversion, tau=tau,
)
mean_uncertainty = predictive_covariance - sigma
print(pd.DataFrame({"Prior (%)": pi * 100, "Hand update (%)": hand_mean * 100,
                    "Toolkit posterior (%)": posterior_mean * 100}).to_string(float_format=lambda x: f"{x:.4f}"))
print(f"Prior spread: {prior_spread:.3%}; posterior spread: {float((P @ posterior_mean).iloc[0]):.3%}")
```
<Editor id="bl-posterior-worked-example" />

**Try it:** set the view to the prior spread, `Q.iloc[0] = prior_spread`, and rerun. The mean does not move because the innovation is zero, but posterior uncertainty still falls: a consistent informative signal adds precision. Restore the 8% view before continuing with the default worked results.

## Three Different Covariance Matrices

Suppose future excess returns satisfy $\mathbf R^e\mid\boldsymbol\mu\sim\mathcal N(\boldsymbol\mu,\Sigma)$, independently of the view errors conditional on the mean. The law of total covariance gives:

$$\operatorname{Cov}(\mathbf R^e\mid Q)=\Sigma+M.$$

Keep the roles separate:

| Matrix | Meaning |
| --- | --- |
| $\Sigma$ | Variability of future returns conditional on their mean |
| $M$ | Posterior uncertainty about the expected-return vector |
| $\Sigma+M$ | Posterior predictive covariance of future returns |

**The second result returned by `pok.black_litterman()` is $\Sigma+M$.** Subtract $\Sigma$ to obtain $M$. A smaller uncertainty about a mean does not eliminate the underlying randomness of returns.

```python:line-numbers
view_vector = P.iloc[0].to_numpy()
uncertainty_comparison = pd.Series({
    "Prior mean-spread uncertainty": np.sqrt(view_vector @ C.to_numpy() @ view_vector),
    "Posterior mean-spread uncertainty": np.sqrt(view_vector @ mean_uncertainty.to_numpy() @ view_vector),
    "Conditional return-spread volatility": np.sqrt(view_vector @ sigma.to_numpy() @ view_vector),
    "Predictive return-spread volatility": np.sqrt(view_vector @ predictive_covariance.to_numpy() @ view_vector),
})
print((uncertainty_comparison * 100).rename("Standard deviation (percentage points)").to_string(float_format=lambda x: f"{x:.3f}"))
```
<Editor id="bl-uncertainty-decomposition" />

For the default inputs, posterior uncertainty in the mean spread is about **3.082 percentage points**, while predictive spread volatility is about **19.736%**. They answer different questions and should not share an unlabeled “risk” column.

## View Strength and the Role of Tau

### A Single-View Confidence Scale

For one view with prior variance $v=PCP^T>0$, define a scale $0<c\leq1$ by:

$$\Omega=\frac{1-c}{c}v.$$

Then $v/(v+\Omega)=c$, so the posterior viewed mean is:

$$P\mu_{BL}=(1-c)P\Pi+cQ.$$

Here “confidence” is an **update-weight parameter** for this construction, not a probability that the view is true. At $c=0$ we explicitly omit the view; at $c=1$ it becomes exact. With multiple correlated or overlapping views, a separate scalar confidence does not generally describe each final update so simply.

```python:line-numbers
confidence_rows = []
for confidence in [0.0, 0.25, 0.5, 0.75, 1.0]:
    if confidence == 0:
        mean_c, predictive_c = pok.black_litterman(reference_weights, sigma, P.iloc[:0], Q.iloc[:0],
                                                  delta=risk_aversion, tau=tau)
    else:
        omega_c = Omega * (1 - confidence) / confidence
        mean_c, predictive_c = pok.black_litterman(reference_weights, sigma, P, Q, Omega=omega_c,
                                                  delta=risk_aversion, tau=tau)
    weights_c = pok.bl_portfolio_weights(mean_c, sigma, delta=risk_aversion)
    confidence_rows.append([confidence, float((P @ mean_c).iloc[0]), weights_c["Equity"]])
confidence_table = pd.DataFrame(confidence_rows, columns=["Confidence", "Posterior spread", "Equity weight"])
print(confidence_table.to_string(float_format=lambda x: f"{x:.4f}"))
print("\n<ECHARTS_DATA>" + json.dumps({
    "confidenceMean": {
        "title": "One View: Strength of the Mean Update",
        "xAxis": {"type": "value", "name": "View update weight", "min": 0, "max": 1},
        "yAxisName": "Expected annual return spread (%)",
        "series": {"Posterior spread": (confidence_table[["Confidence", "Posterior spread"]] * [1, 100]).values.tolist()},
    },
    "confidenceWeights": {
        "title": "One View: Constrained Equity Allocation",
        "xAxis": {"type": "value", "name": "View update weight", "min": 0, "max": 1},
        "yAxisName": "Equity portfolio weight (%)",
        "series": {"Equity": (confidence_table[["Confidence", "Equity weight"]] * [1, 100]).values.tolist()},
    },
}, allow_nan=False))
```
<Editor id="bl-confidence-sensitivity" />

The mean spread moves linearly under this single-view construction, while long-only portfolio weights can hit bounds. A strong enough view can produce a concentrated allocation even when the posterior update itself is smooth.

### Why Tau Sometimes Cancels

With $C=\tau\Sigma$ and the default $\Omega=\tau\operatorname{diag}(P\Sigma P^T)$, the common $\tau$ factor cancels from the gain in the posterior **mean**. It remains in $M$, so predictive covariance can change. If instead $\Omega$ is held fixed as $\tau$ changes, the relative weight of the prior and views changes and the mean generally moves.

```python:line-numbers
tau_rows = []
for tau_value in [0.01, 0.05, 0.20]:
    scaled_mean, scaled_predictive = pok.black_litterman(reference_weights, sigma, P, Q,
                                                        delta=risk_aversion, tau=tau_value)
    fixed_mean, _ = pok.black_litterman(reference_weights, sigma, P, Q, Omega=Omega,
                                       delta=risk_aversion, tau=tau_value)
    tau_rows.append([tau_value, float((P @ scaled_mean).iloc[0]), float((P @ fixed_mean).iloc[0]),
                     np.sqrt(view_vector @ (scaled_predictive - sigma).to_numpy() @ view_vector)])
tau_table = pd.DataFrame(tau_rows, columns=["Tau", "Spread: scaled Omega", "Spread: fixed Omega", "Posterior mean-spread SD"])
print(tau_table.to_string(float_format=lambda x: f"{x:.5f}"))
```
<Editor id="bl-tau-and-view-uncertainty" />

This is why tuning tau without stating the Omega convention is ambiguous. Keep both the prior-uncertainty and view-uncertainty assumptions visible.

## From Posterior Means to Portfolio Weights

Updating beliefs does not specify trading constraints. We now impose fully invested, long-only risky weights:

$$\max_{\mathbf w}\left(\mathbf w^T\mu_{BL}-\frac\delta2\mathbf w^T V\mathbf w\right),
\qquad \mathbf1^T\mathbf w=1,\quad w_i\geq0.$$

Choose $V$ explicitly. Using $V=\Sigma$ retains the original conditional-risk model; using $V=\Sigma+M$ accounts for mean uncertainty in predictive return risk. These are different allocation specifications. Neither should be selected silently by a helper or confused with normalizing unconstrained risky positions.

```python:line-numbers
weights_prior_risk = pok.bl_portfolio_weights(posterior_mean, sigma, delta=risk_aversion)
weights_predictive_risk = pok.bl_portfolio_weights(posterior_mean, predictive_covariance, delta=risk_aversion)
allocation_comparison = pd.DataFrame({"Reference": reference_weights, "BL: conditional risk": weights_prior_risk,
                                     "BL: predictive risk": weights_predictive_risk})
print((allocation_comparison * 100).to_string(float_format=lambda x: f"{x:.3f}"))
print("\n<ECHARTS_DATA>" + json.dumps({
    "allocationChoice": {
        "type": "bar", "title": "Same Posterior Mean, Explicit Risk-Matrix Choice",
        "xAxis": {"type": "category", "data": assets.tolist()}, "yAxisName": "Portfolio weight (%)",
        "series": {name: (allocation_comparison[name] * 100).tolist() for name in allocation_comparison},
    },
}, allow_nan=False))
```
<Editor id="bl-constrained-allocation" />

With conditional covariance, the default posterior implies approximately **77.37% Equity and 22.63% Bonds**. For two assets, this result can be independently checked by substituting $w_B=1-w_E$ into the utility objective and solving:

$$w_E^*=\frac{\mu_E-\mu_B+\delta(\Sigma_{BB}-\Sigma_{EB})}
{\delta(\Sigma_{EE}+\Sigma_{BB}-2\Sigma_{EB})},$$

then restricting the result to $[0,1]$. The predictive-risk allocation generally differs. With no views, the original reference is recovered using $\Pi$ and $\Sigma$ when it is feasible. Using the enlarged predictive covariance $(1+\tau)\Sigma$ instead need not reproduce that reference under the same risk aversion and budget constraint.

### Exact Views Still Leave Return Risk

```python:line-numbers
exact_omega = pd.DataFrame(0.0, index=P.index, columns=P.index)
exact_mean, exact_predictive = pok.black_litterman(reference_weights, sigma, P, Q, Omega=exact_omega,
                                                 delta=risk_aversion, tau=tau)
exact_mean_spread_variance = float(view_vector @ (exact_predictive - sigma).to_numpy() @ view_vector)
print(f"Exact posterior expected spread: {float((P @ exact_mean).iloc[0]):.3%}")
print(f"Mean-spread uncertainty variance: {exact_mean_spread_variance:.3e}")
print(f"Predictive spread volatility: {np.sqrt(view_vector @ exact_predictive.to_numpy() @ view_vector):.3%}")
```
<Editor id="bl-exact-view-limit" />

The expected spread is exactly 8%, and its mean uncertainty is zero up to roundoff. Future return-spread volatility is still about **19.494%**. Certainty about an expected value is not certainty about the realized outcome.

## A Historical Three-Industry Illustration

### Estimate Risk Before Setting the Decision

Use the bundled value-weighted industry returns for **Food, Steel, and Finance**. The training period is January 2000–December 2009; the evaluation period will be January 2010–December 2018. The selection is illustrative, not a claim that these industries represent the whole market.

Estimate monthly covariance using the previous chapter's 50% constant-correlation shrinkage, then report it on the annualized basis by multiplying by 12. Views below refer to **annualized arithmetic expected excess returns**, not forecasts of CAGR. Tau is specified on this same reporting basis rather than inferred automatically from the number of months.

```python:line-numbers

print(f"Held out: {held_out_returns.index[0]} to {held_out_returns.index[-1]}, {len(held_out_returns)} months")

```

### Correlated Views Are a Different Information Model

If the two view errors share information, a diagonal Omega may overstate independent evidence. Keep their marginal error variances fixed and introduce a 0.5 error correlation. This changes the joint update; it does not change the supplied asset covariance or the view statements themselves.

```python:line-numbers
view_error_sd = np.sqrt(np.diag(historical_omega))
correlated_omega = historical_omega.copy()
correlated_omega.iloc[0, 1] = correlated_omega.iloc[1, 0] = 0.5 * view_error_sd[0] * view_error_sd[1]
correlated_mean, _ = pok.black_litterman(historical_reference, annual_covariance, historical_P, historical_Q,
                                       Omega=correlated_omega, delta=historical_delta, tau=historical_tau)
print(pd.DataFrame({"Independent view errors (%)": historical_mean * 100,
                    "Correlated view errors (%)": correlated_mean * 100}).to_string(float_format=lambda x: f"{x:.3f}"))
```

Do not duplicate the same opinion as two supposedly independent views to manufacture confidence. Perfectly redundant exact information can make the conditioning system singular, which the toolkit reports explicitly.

## Chapter Summary

- Reverse optimization produces implied **excess means** from a reference allocation, covariance, and risk aversion; it does not estimate future returns directly.
- The pick matrix, view vector, and view-error covariance describe what is believed and how uncertain that information is. Horizons, units, and labels must agree.
- The posterior update responds to the innovation $Q-P\Pi$, with effects transmitted through covariance.
- Uncertainty about expected returns $M$ differs from conditional return covariance $\Sigma$ and predictive covariance $\Sigma+M$.
- Confidence conventions determine how tau matters. Under proportional Omega, tau cancels from the posterior mean but not its uncertainty.
- Portfolio constraints and the risk matrix remain explicit choices after updating beliefs. Exact expected-return views still leave realized return risk.

For the original portfolio framework, see Fischer Black and Robert Litterman, “Global Portfolio Optimization,” *Financial Analysts Journal*, 48(5), 1992, pp. 28–43, [doi:10.2469/faj.v48.n5.28](https://doi.org/10.2469/faj.v48.n5.28).
